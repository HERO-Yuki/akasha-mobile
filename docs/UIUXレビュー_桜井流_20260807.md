# 🎮 桜井政博流 UI/UX 診断レポート — Akasha Mobile v0.2

- 対象: `App_051_Akasha/mobile`（Expo / React Native、iOS サイドロード運用）
- 日付: 2026-08-07
- 使用スキル: `sakurai-ui-ux`（7大コア・プリンシプル + アプリ向けチェックリスト）
- 前提（フェーズ1で置いた仮定）
  - **ターゲット**: 陽彩ひとり。作り手＝使い手。iPhone、リテラシーは高い
  - **目的**: Dropbox `/podcast` に溜まった音声を消化し、Inbox を空にする
  - **最頻操作**: ①Inbox から1本タップして再生 → ②聴き終える（自動アーカイブ）→ ③たまに★退避 → ④たまに一括削除
  - **利用シーン**: 移動中・作業中。**画面を見ずにポケットの中で操作することがある**

---

## 💡 全体所感

**一番良い**のは色の統一。ダーク `#17181C` に琥珀 `#E8884D` の1アクセントだけで、
状態（現在再生・進捗・有効なトグル）を全部表現しきっている。色数を増やさずに
情報を分けられているのは、原則7の観点で素直に上手い。夜や移動中に聴くアプリとして
トーンも合っている。

**最大の課題**は原則2と原則5。とくに核心はここ:

> **お気に入り登録が「一括削除モーダルの中で、削除対象から除外する」という裏口にしか無い。**

これは「一括処理のついでに実装した」という**作り手の都合が、そのまま操作体系になった**
典型例。ユーザーの頭の中では「★を付ける」は独立した肯定的な行為なのに、
アプリでは「削除フローに入って、削除しない方を選ぶ」という否定形の遠回りを強いる。
「お気に入りの登録方法がわかりづらい」という実感は、まさにこれが原因。
スワイプ操作の追加は正しい方向の対処。

もうひとつ全体に効いているのが**無反応**。タップしても、押しても、終わっても、
アプリはほとんど何も返してこない。原則4の観点では最も損をしている部分。

## 🔍 コア・プリンシプル評価

### ⚡ スピード＆レスポンス（遅さは罪）— **要改善**

**分析**

1. **起動のたびに全件取得を待つ。** `App.tsx` の `reload()` は `files/list_folder` を
   再帰で全ページ舐めてから初描画する。前回の一覧をどこにも保存していないので、
   毎回ゼロから待たされる。ファイルが増えるほど起動が重くなる一方。
2. **再生タップから音が出るまで完全に沈黙する。** `playTrack()` は
   `getTemporaryLink()` のラウンドトリップ→`player.replace()`→`play()` の順。
   その間 1〜2秒、画面は何も変わらない。**押せていないのか、遅いだけなのかが区別できない。**
3. **速度切替が7段階の順送り。** `SPEEDS = [1, 1.25, 1.5, 1.75, 2, 0.5, 0.75]`。
   1.0x から 0.75x にしたいだけで**6回タップ**する。しかも1周してしまうと
   「行き過ぎた、もう一周」になる。これは原則1が最も嫌う「時間を奪う」形。
4. **シークが「タップして飛ぶ」だけでドラッグできない。** バー幅を約300pxとすると、
   1時間の音源では **1px ≒ 12秒**。狙った場所には絶対に止まらない。
   聞き逃した箇所に戻る操作が実質使えない。

**具体的な改善案**

- 一覧を AsyncStorage にキャッシュし、**起動直後は前回の一覧をそのまま描いて**
  裏で更新する（stale-while-revalidate）。体感の起動時間がほぼゼロになる。
- タップした瞬間に、その行をハイライトし、プレイヤーバーのタイトルを
  「読み込み中… ファイル名」に差し替える。**待たせるなら、待っていることを見せる。**
- 速度は 0.75 / 1.0 / 1.25 / 1.5 / 2.0 の5段階に絞り、**長押しで一覧から直接選べる**
  ようにする（順送りは1タップで隣に行きたい人向けに残す）。
- シークバーを `PanResponder` でドラッグ対応にする（スワイプ実装と同じ仕組みで済む）。
  ドラッグ中は現在位置の時刻を大きく表示する。

### 📐 視認性と情報優先度（大事なものをより大きく）— **要改善**

**分析**

1. **「アーカイブを一括削除…」が一等地を独占している。** 月に1回押すかどうかの
   破壊的操作が、リストのすぐ上に**横幅いっぱいの赤枠**で常駐する。
   原則2（頻度と重要度に応じてサイズと配置を変える）を、そのまま逆に実行している。
   しかも赤枠は視線を強く引くので、本来見たいリストから注意を奪い続ける。
2. **プレイヤーバーの5ボタンがほぼ同格。** 実際の使用頻度は
   `▶ ≫ -15s/+30s > 次へ > 速度` なのに、`速度` `-15s` `+30s` `次へ` は
   全部 `minWidth: 52` の同じ箱。▶ だけ 52px 円形で少し目立つ程度。
   **一番押す ▶ が、一番押さない 速度 と同じ列に並んでいる。**
3. **プレイヤーバーが常時 170px を占める。** 未再生（`未再生 — ファイルをタップ`）の
   ときでもシークバーもボタンも全部出ていて、画面の約2割が死んでいる。
   リストの表示件数がそのぶん減る。
4. **行のファイル名が1行で切れる。** `numberOfLines={1}`。ポッドキャストの
   ファイル名は先頭が共通（`番組名_第121回_…`）になりがちで、**先頭だけ見えても
   全部同じに見える**。区別に必要な情報は後半にあることが多い。

**具体的な改善案**

- 一括削除ボタンは**リストの最下部**（スクロールしきった先）へ移す。
  「全部見終わってから片付ける」という実際の順番とも合う。
- ▶ を 52 → **68〜72px** に拡大。`速度` はプレイヤーバーから外し、
  トグル行（`連続再生` `自動アーカイブ` の並び）へ小さく移す。
  `-15s` `+30s` は残す（ポッドキャスト用途では頻度が高い）。
- 未再生のときはプレイヤーバーを**タイトル1行＋▶ だけの細い帯**に畳む。
  再生を始めたら展開する。リストが3〜4行ぶん増える。
- ファイル名を `numberOfLines={2}` にする。もしくは先頭の共通部分を
  フォルダ名として畳んで、回次や差分だけを大きく出す。

### 🌐 直感性と導線（言語がなくてもわかるように）— **要改善**

**分析**

1. **一括削除モーダルのチェックが反転している。** `☑` が「削除される」で、
   `★`（タップして除外）が「お気に入りへ」。世間のチェックボックスは
   「☑＝自分が選んだもの」だが、ここでは **☑＝何もしなかったもの＝消えるもの**。
   初見で必ず読み違える。しかも読み違えた結果が**ファイルの消失**なので、間違いのコストが高い。
2. **記号が全部テキスト文字。** `▶` `⏸` `☑` `★` `✓` はフォント依存で、
   端末やOSバージョンで見た目が変わる。App_050（はなまる）では
   「**絵文字は使わない・インラインSVGで統一**」という原則を立てているのに、
   こちらは逆をやっている。同じ作り手のプロダクト間で判断がぶれている。
3. **「接続解除」がタブ行に常駐している。** 使用頻度ほぼゼロ、押すと全データへの
   アクセスを失う操作が、毎日見るタブと同じ高さに並んでいる。
   （※これは今回のロゴ行削除で私が移した結果。移し先が適切でなかった）
4. **空状態が説明になっていない。** 「このビューにはファイルがありません」は
   状態を言い換えただけで、**次に何をすればいいか**を何も教えない。
   原則3が戒める「項目名の言い換えに過ぎないヘルプ」と同じ構造。

**具体的な改善案**

- 一括削除モーダルは**既定を全部「残す」にして、消したいものを選ばせる**方向に反転する。
  少なくとも `☑` をやめ、`🗑 削除` / `★ 残す` のように**行き先そのものをラベルにする**。
- `▶` `⏸` `★` は最低限インラインSVG化する（App_050 の判断と揃える）。
- 「接続解除」はタブ行から外し、**プレイヤーバーの設定トグル行の末尾**か、
  タブの長押しに逃がす。
- 空状態を用途別にする。Inbox が空 → 「聴くものはありません。おつかれさま」、
  お気に入りが空 → 「アーカイブ画面で行を左にスワイプすると★に入ります」。
  **空の画面は、操作を教える最高の場所。**

### 🎯 操作の手応えとフィードバック（ノーリアクションを排除せよ）— **要改善**

ここが7原則の中で**最も損をしている**。

**分析**

1. **`Pressable` に押下時のスタイルがひとつも無い。** すべて
   `style={[s.row, isCur && s.rowCurrent]}` のような静的スタイルで、
   `pressed` を見ていない。**タップしても画面は1ドットも変わらない。**
   行も、再生ボタンも、±15秒も、タブも、全部そう。
2. **振動が一切ない。** ポケットの中で操作しうるアプリで、触覚フィードバックがゼロ。
   画面を見ずに「効いたかどうか」を知る手段が存在しない。
3. **成功しても何も起きない。** 移動が成功すると行が黙って消えるだけ
   （v0.2 でトーストを足したが、まだ控えめ）。
4. **連続再生が終端に達したときも無言。** `step(1)` は範囲外なら何もしないので、
   最後の1本が終わると**ただ静かになる**。故障と区別がつかない。

**具体的な改善案**

- 全 `Pressable` を `style={({pressed}) => [...]}` 形式にして、押下中は
  `opacity: 0.6` か背景を1段明るく。**これは30分で全部入る割に効果が最大。**
- `expo-haptics` を入れ、①再生開始 ②スワイプ閾値の通過 ③移動の完了
  の3点で軽く振動させる。とくに**2段階スワイプでは閾値通過の振動が必須**
  （どちらが発動するか指の感触でわかる）。
- 連続再生の終わりに「Inbox を聴き終えました」を出す（原則6に繋がる）。

### 👤 遊び手視点（それ、説明して回るつもりなの？）— **要改善**

**分析**

1. **お気に入り登録の裏口**（全体所感に書いたとおり）。実装の都合が操作体系になっている。
2. **取り消しがどこにも無い。** スワイプで移動しても、一括削除を実行しても、
   アプリ内から元に戻す手段がない。Dropbox 上のファイル移動なので物理的には
   取り返せるが、それは「PCのDropboxを開いて手で戻せ」という**作り手都合の押し付け**。
   **2段階スワイプを入れるなら、取り消しは必須。**
3. **7日で突然使えなくなるのに、アプリは何も予告しない。** サイドロードの制約は
   ユーザー（＝作り手本人）の選択だが、それでも**「明日切れます」の一言があるかないか**で
   体験は全く違う。今回まさに「使えなくなったのでどうすれば」となったのが証拠。
   原則5が問う「それ、事情を説明して回るつもりなの？」がそのまま当てはまる。
4. **エラーメッセージ**は v0.2 で「コード＋原因＋対処」に直したので **解消済み**。
   これは原則5の正しい実装。

**具体的な改善案**

- 移動を伴う操作のトーストに**「元に戻す」ボタン**を付ける（表示は5〜6秒）。
  実装は `moveToDir` を逆方向に呼ぶだけで、既存の仕組みで足りる。
- **署名期限のカウントダウン**をアプリ内に持つ。初回起動日を保存し、
  6日目から「あと1日で署名が切れます」をタブ行の下に細く出す。
  切れる前に気づければ、Sideloadly を繋ぐだけで途切れない。
- お気に入り登録をスワイプで前面に出す（今回の対応）。**一括削除モーダルは
  「削除の道具」に戻し、お気に入りの入口という兼務をやめる。**

### 🏆 モチベーション駆動と承認（ほめてやれ！）— **要改善（ほぼ未着手）**

**分析**

Inbox Zero は本来、達成感の宝庫。「溜まっていたものが消えた」は
それ自体がごほうびになる構造なのに、**アプリはそれを1ミリも祝わない。**
Inbox が空になったときの表示は `このビューにはファイルがありません` という事務連絡。

同じ作り手が App_050（はなまる）では「今週できたこと」画面と達成演出をわざわざ作り、
設計5原則に「**完了は消さない、積み上げる**」と書いている。
**その思想が App_051 には移植されていない。**

**具体的な改善案**

- Inbox が 0 になった瞬間の演出（琥珀色のフラッシュ1回＋「全部聴きました」）。
  派手である必要はない。**無言でないことが重要。**
- タブの `Inbox 12` を「残り12本・約4時間」に。**あと何をすれば終わるかを数で見せる**と、
  片付ける動機が立つ（原則6の「次の目標まであと何」）。
- 累計の視聴済み本数・時間をどこかに1行。`positions` に `listened` を
  既に持っているので、**新しいデータを増やさずに実装できる。**

### 🎨 世界観とトーンマナー — **良好**

**分析**

- ダーク＋琥珀1アクセントの運用は一貫していて、破綻がない。
  `accent` / `accentStrong` / `accentSoft` の3段で状態を表し分けている設計は堅実。
- `danger` を一括削除にだけ使い、他に赤を散らしていないのも良い。
- 惜しいのは、`Akasha`（アーカーシャ＝万物の記録）という名前の世界観が
  UI上にまったく現れないこと。ただし**ここは無理に足さなくてよい**。
  原則2（余計な装飾を増やさない）を優先すべき場面。
  空状態の文言くらいでトーンを乗せれば十分。

**具体的な改善案**

- 空状態やInbox Zeroの一言に、少しだけ言葉のトーンを乗せる（装飾は増やさない）。

## 🛠️ 明日から使える「即効・改善レシピ」

### 1.【最優先】お気に入りを裏口から出し、取り消しを付ける（原則5・3・4）

**どう直すか**

- 一覧のスワイプ操作を確定させる。左＝片付ける（浅＝アーカイブ／深＝★）、
  右＝ひとつ戻す。スワイプ中は背景ラベルと色が閾値で切り替わる。
- 移動後のトーストに **「元に戻す」** を付ける（5秒）。
- 閾値の通過で軽い振動（`expo-haptics`）。画面を見ずに判別できる。
- 一括削除モーダルは「削除の道具」に戻し、`☑` の反転を解消する。

**得られるメリット**
最頻操作のひとつが「モーダルを開いて除外を選ぶ」から**指1本**になる。
取り消しがあるので2段階スワイプの誤爆が怖くなくなり、思い切って使える。

---

### 2. 押したら反応を返す（原則4）

**どう直すか**

- 全 `Pressable` を `style={({pressed}) => ...}` に書き換え、押下中は
  `opacity: 0.6` または背景を1段明るく。
- 再生タップの瞬間に行をハイライトし、プレイヤーバーを「読み込み中…」にする。
- 連続再生の終端で「Inbox を聴き終えました」。

**得られるメリット**
**作業量が最も小さく、体感の改善が最も大きい。** いま「反応が遅い」と
感じている部分の多くは、実は「反応が無い」ことによる不安が原因。

---

### 3. 画面の面積を、使う頻度どおりに配り直す（原則2・1）

**どう直すか**

- 一括削除ボタンをリスト最下部へ移す（一等地を空ける）。
- ▶ を 68〜72px に拡大。速度切替はプレイヤーバーから外してトグル行へ。
- 未再生時はプレイヤーバーを1行に畳む（リストが3〜4行増える）。
- ファイル名を2行表示に。

**得られるメリット**
一覧の情報量が増え、一番押すボタンが一番押しやすくなる。
「上部のロゴが場所を取る」と感じた問題の本体は、実はここ。

## 良かったところ（遠慮なく）

- **色の統一と抑制**。1アクセントで状態を全部表せている。増やさない判断が良い。
- **95%で視聴済み・聴き終えたら自動アーカイブ**。これは「片付けを操作にしない」
  正しい自動化。ユーザーの手数をゼロにしている点で原則1・5の模範。
- **`trash/` を一覧から隠す**割り切り。消したものを見せない徹底は迷いがなくて良い。
- **v0.2 のエラー表示**（コード＋原因＋対処＋生ログ）。
  「作り手都合をユーザーに押し付けない」を、後付けでもきちんとやり直せている。
